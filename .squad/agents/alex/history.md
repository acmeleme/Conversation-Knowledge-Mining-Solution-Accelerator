- 2026-06-08: **CKM-TokenUsage metric emission fix.** Root cause 1 (primary): OTel `PeriodicExportingMetricReader` defaults to 60-second export interval. On ephemeral/F1 App Service instances idle-timeout container recycling discards buffered counter data before the first export fires. Fixed in `event_utils.py` by starting a background daemon thread that calls `provider.force_flush(timeout_millis=5000)` immediately after every `counter.add()`. Root cause 2 (secondary): attribute key `"User ID"` (with space) is non-standard for OTel metric attributes; Azure Monitor's pipeline may silently drop space-keyed dimension values. Fixed in `chat_service.py` by renaming to `"user_id"`. Key constraint: `azure.monitor.events.extension.track_event()` writes to `customEvents` (direct/immediate); OTel `Counter.add()` writes to `customMetrics` (batched, periodic) — the dashboard queries `customMetrics`, so the Counter path must be fixed rather than replaced with `track_event`. The OTel ProxyMeterProvider automatically upgrades proxied counters to real SDK counters once `configure_azure_monitor()` runs, so import order is safe. 8 new unit tests added in `tests/test_token_usage_metric.py`; 23 existing tests unaffected.
