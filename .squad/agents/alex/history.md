# Alex History

## Learnings
- 2026-05-25: Initialized the manual SDD framework scaffolding for this repository by creating envisioning, feature spec, ADR, and implementation plan folders plus project-level Copilot instructions. This establishes a consistent place for product intent, architecture decisions, and execution plans now that the devsquad plugin is unavailable.
- 2026-05-25: The FastAPI backend boots four agents in `src/api/app.py`: `ConversationAgentFactory`, `SearchAgentFactory`, `SQLAgentFactory`, and `ChartAgentFactory`. The conversation path is different from the others: it uses Semantic Kernel `AzureAIAgent` plus the local `ChatWithDataPlugin`, while search/SQL/chart agents are created directly with `azure.ai.projects.AIProjectClient`.
- 2026-05-25: Persistent chat history already lives in Cosmos DB via `HistoryService` and `CosmosConversationClient`, keyed by Easy Auth `user_principal_id`. This makes Memory Store a personalization/context layer, not a replacement for the existing chat history feature.
- 2026-05-25: The frontend already establishes a stable user context through Easy Auth. `src/App/src/api/api.ts` fetches `/.auth/me`, stores the Entra object ID in local storage, sends the Bearer `id_token`, and includes `X-Ms-Client-Principal-Id` on API calls; the backend can also read tenant/object claims from `auth_utils.py`.
- 2026-05-25: No Memory Store integration exists yet in the codebase. The backend requirements pin `azure-ai-projects==1.0.0`, so adopting Foundry Memory preview should include validating or upgrading to a newer `azure-ai-projects` version that exposes `project_client.beta.memory_stores` and `MemorySearchPreviewTool`.
- 2026-05-25: Implemented Foundry Memory in `src/api/services/foundry_memory_service.py`, `src/api/services/chat_service.py`, `src/api/common/config/config.py`, `src/api/requirements.txt`, and `src/api/.env.memory.example`. The backend now derives scope from Easy Auth (`user_principal_id` + `tid`), prepends retrieved memories to the conversation prompt, and schedules `begin_update_memories` after the streamed answer completes.
- 2026-05-25: Reused the existing Azure credential pattern from the agent factories via `get_azure_credential(client_id=config.azure_client_id)` and wrapped sync Memory Store SDK calls in `asyncio.to_thread()` for additive, non-blocking behavior. `ChatService` now guards thread reuse when a test/dummy agent has no SDK client.
- 2026-05-25: In practice, Foundry Memory required `azure-ai-projects>=2.0.0`; the requested `>=1.0.0b4` floor still resolves to `1.0.0`, which does not expose `project_client.beta.memory_stores` or `MemorySearchOptions`. I also added `tests/api/services/test_chat_service_memory.py` to cover scope building, prompt augmentation, and post-stream memory updates.
- 2026-05-26: Full data-flow audit (Leme request). Found 7 bugs — see `.squad/decisions/inbox/alex-bugs-audit.md`. Key fixes applied: (1) `ChartFilter.tsx` P0 crash: `filtersMeta?.Topic?.filter()` returned `undefined` when Topic list was absent; fixed with `(filtersMeta?.Topic ?? []).filter()`. (4) SQL injection in `fetch_chart_data()` WHERE clause flagged but not yet fixed (needs full parameterized-query refactor). (5) `adjust_processed_data_dates()` running on every API call is a performance concern — flagged for team.
- 2026-05-26: Pattern noted: `FoundryMemoryService.build_scope()` is a static method and safe to call from `api_routes.py` without instantiating the full service (avoids SDK init cost on every `/api/me` call). The `get_tenantid()` utility in `auth_utils.py` reads `x-ms-client-principal` base64 payload and checks both top-level `tid` and claims array — covers both Easy Auth v1 and v2 formats.
- 2026-05-26: Created `scripts/seed_memory_store.py` to simulate 100 call center conversations in Portuguese and populate the Azure AI Foundry Memory Store (`memory-store-callcenter-100`). Script uses the same `AIProjectClient` pattern as `FoundryMemoryService`, wraps sync `begin_update_memories()` calls in `asyncio.to_thread()`, includes exponential backoff retry logic for rate limits (3 attempts, base delay 2s), and generates realistic conversations across 6 categories (sales, support, complaints, status, account, general). Each conversation is 2 turns (user + assistant) with automatic greeting variations. Documented in `scripts/README.md` with usage, troubleshooting, and customization instructions.
- 2026-05-28: Diagnosed and fixed the persistent "Dev Local" auth bug in production. Root cause: Easy Auth v2 returns HTTP 401 with **empty body** (not `[]` JSON) for unauthenticated/expired-session requests when the request is treated as an API call (non-browser `Accept` header). `r.json()` on an empty body throws `SyntaxError`, which is caught by `.catch()` → "Dev Local" instead of redirecting to login. Fix: refactored `useEffect` in `App.tsx` to `async/await` with an explicit `if (!r.ok)` guard before calling `r.json()` — expired sessions now redirect to `/.auth/login/aad` instead of showing "Dev Local". Also created `src/App/nginx.conf` with `Cache-Control: no-cache` on `index.html` and `try_files` for React Router, and updated both Dockerfiles to use it (EXPOSE corrected 3000→80 to match nginx default + WEBSITES_PORT default).
